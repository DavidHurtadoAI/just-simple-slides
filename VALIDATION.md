# Local validation — 0.1.8

Checked on 17 October 2026, Windows desktop, in the actual Obsidian application with an isolated vault and application profile.

- `npm run check`: the full official Obsidian ESLint recommended configuration, CSS compatibility checks, 32 unit tests, strict TypeScript, production build, and version/asset packaging passed with zero lint warnings. The sentence-case rule preserves the plugin name as a brand; no rules are disabled.
- `scripts/qa-obsidian.mjs`: 99 integration checks passed against the actual Obsidian application, with no runtime errors. The JSON report and original screenshots are in the ignored `qa/` folder.
- Checked that opening slides from Markdown creates a new tab, preserves the original native editor and cursor, and follows that cursor to the matching slide. Repeating the command from Markdown creates another slide tab. The lower panel has no full source selector.
- Checked **Edit source** reuses the original native editor, focuses and scrolls to the selected first, middle, and last slides, and leaves both tabs and content intact. Checked navigation after reordering, pending private notes, original CRLF offsets, reading-to-editing mode, opening a missing note tab, and reusing/focusing a real Obsidian pop-out window. The action remains visible as an accessible icon in a narrow pane.
- Checked one selector per private callout, source order, optional names, repeated names, unnamed and empty areas. Slides without callouts show a non-editable hint; adding the first callout in native Markdown replaces it with an area editor.
- Checked actual editor input into the second area, byte-for-byte preservation outside that body, arbitrary Markdown without a type form, independent same-name areas, clearing a body without deleting the callout, undo/redo across area selection, and autosave to the real file. CRLF bodies load as separate logical editor lines, and the area replacement preserves surrounding bytes in memory. The native Obsidian editor normalizes CRLF to LF on save; checked that every line survives that normalization.
- Checked live selector updates after renaming, adding and removing callouts in the native Markdown editor, plus Left/Right, Home and End navigation.
- Checked computed font family and size on both editors' actual CodeMirror content elements, including a custom text font and 23px text setting.
- Checked immediate sharing of unsaved edits between the native editor and two slide tabs, preservation of native undo history, rapid native-to-area editing, and combined autosave. Closing a tab with pending notes must not overwrite a later native undo. Checked independent native tab closure, editing and saving with only slide tabs open, and reopening native Markdown.
- Checked all private callouts and their names stay out of previews, thumbnails and native fullscreen while ordinary callouts remain visible. Names do not set slide types or layout attributes. Folded/expanded/case-insensitive callouts, private headings, nested callouts, lazy continuation and literal code examples were also checked.
- Unit coverage checks exact header preservation, CRLF, Markdown indentation, nested editing, missing areas, duplicate areas, empty bodies, quoted separators, and final newline handling. Saved layouts ignore the retired source mode and validate selected area indices.
- Checked native close-tab controls leave the original Markdown editor open and the fixture byte-for-byte intact. Checked undo/redo across slide navigation, duplicate, move, and delete.
- Checked all six demo slides and a dense stress slide for content bounds, local images, image-only composition, and text/image columns.
- Checked native fullscreen, starting from the selected slide, arrows, Space, Home, End, Esc, and F5. Presentation leaves Markdown unchanged and inherits the theme background.
- Checked pointer drags on both panel dividers, keyboard resizing, double-click reset, and saved dimensions/area selection.
- Checked native thumbnail drag-and-drop, selection following the moved slide, immediate native Markdown updates, cleanup of drag feedback, single-step undo/redo, image/callout preservation, and cancellation outside the rail. Unit tests cover all position pairs, blank slides, frontmatter, separator formatting, and missing final newlines.
- Inspected screenshots in light/dark modes with the vault's Border theme, including the lower editor's Notes and Cues selectors. Checked the editor in a 390px desktop viewport with the native sidebar collapsed and a scrolling selector row.
- Minimum API version is 1.7.2, matching `Workspace.revealLeaf` (since 1.7.2) and `View.scope` (since 1.5.7) in the official Obsidian API declarations. The public 0.1.5 entry in `versions.json` is also corrected so older apps are not directed to an unsupported version.
- CSS uses no `!important` or unsupported Chromium 114 features. The CSS gate was checked against the published 0.1.5 stylesheet: it detects both its scrollbar warning and its `!important` declarations, while accepting the corrected stylesheet.
- `npm audit` reports zero known vulnerabilities, including development dependencies. The development-only Moment dependency from the Obsidian type package is pinned to its compatible fixed version.
- Tagged releases build and attest all three installable files in GitHub Actions, verify provenance before publishing, and then download and verify the published bytes and attestations. Only `main.js`, `manifest.json`, and `styles.css` are attached.

This is desktop validation. A narrow desktop viewport does not establish physical iOS/Android compatibility. Third-party interactive embeds have not been comprehensively tested.

The optional integration script requires Playwright on `NODE_PATH` and an isolated Obsidian instance listening at `http://127.0.0.1:9234`. It refuses a vault whose name/path do not match the test vault under this project. Playwright is a development test tool, not a plugin runtime dependency.
